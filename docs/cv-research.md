# План исследования поиска по фотографии

> Superseded: реализованный pipeline и утверждённые ML-решения описаны в [ml.md](./ml.md).
> В частности, отдельный HTTP-encoder не добавлялся — модель работает в существующем worker.

Текущий MockPhotoMatcher не оценивает сходство. Его результаты нельзя использовать как
метрику распознавания животных или вероятность совпадения.

1. Согласовать задачу: retrieval кандидатов для ручного просмотра, а не доказательство
   идентичности. Зафиксировать целевые виды животных и допустимые условия фото.
2. Получить законно собранный dataset с согласиями, правилами хранения/удаления и разметкой
   повторных наблюдений. Отделить фотографии одного животного между train/validation/test
   без утечки. Не извлекать или публиковать EXIF/GPS.
3. Определить baseline и метрики Recall@K, Precision@K, latency, throughput, стоимость,
   устойчивость к освещению, ракурсу, частичному перекрытию и малому корпусу. Отдельно
   проверить сложные негативные примеры похожих животных.
4. Сравнить подходы и лицензии; выбор модели выполнить только после измерений.
   География/вид/дата остаются SQL-фильтрами, а не заменяются непроверенным CV-score.
5. Реализовать вне API HTTP image encoder с versioned контрактом, ограничением размера,
   timeout и наблюдаемостью. RealPhotoMatcher использует encoder и EmbeddingRepository;
   PostgreSQL/pgvector хранит versioned embeddings и индексы.
6. Добавить migration, backfill, перевычисление при смене модели и правила удаления
   embeddings вместе с media. Обеспечить fencing/повторобезопасность существующей очереди.
7. Оценить качество на закрытом test set. Не представлять raw score как вероятность без
   отдельной калибровки. Явно разделять mock и real provider в API и интерфейсе.
8. Провести ограниченный pilot, мониторить качество и откаты. Ошибки real provider должны
   давать явное состояние failure/retry; скрытый fallback на mock запрещён.

Storage Protocol позволяет позднее заменить однохостовый volume объектным хранилищем.
PhotoMatcher Protocol оставляет HTTP, ownership, SQL scope, queue и polling независимыми
от выбора CV реализации.
